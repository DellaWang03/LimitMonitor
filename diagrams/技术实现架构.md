### 1.2 核心设计原则

- **分层解耦**：各层职责单一，通过接口通信
- **流水线处理**：3阶段ETL顺序执行，数据逐层加工
- **配置驱动**：限额参数、数据源路径均外部化配置
- **无状态设计**：Web层无状态，数据全部落盘
- **可追溯性**：历史数据按日归档，支持时间回溯

```python
def calculate_usage_rate(holding: float, limit: float) -> float:
    """限额使用率 = 当前持仓 / 配置限额"""
    if limit == 0 or pd.isna(limit):
        return 0.0
    return holding / limit

def determine_alert_level(usage_rate: float) -> str:
    """预警分级"""
    if usage_rate >= 0.95:
        return "严重超限"
    elif usage_rate >= 0.90:
        return "预警"
    elif usage_rate >= 0.80:
        return "提示"
    else:
        return "正常"
```

```python
class WindCodeResolver:
    def standardize_code(self, code: str) -> str:
        """去除交易所后缀，统一为Wind代码"""

        return code.split('.')[0] if '.' in code else code
    
    def resolve_issuer_code(self, issuer_name: str) -> str:
```

### 4.3 省份标准化

**问题**：省份名称存在多种写法（"北京市"/"北京"/"京"）  
**解决方案**：

```python
class ProvinceNormalizer:
    PROVINCE_MAPPING = {
        '北京': '北京市',
        '京': '北京市',
        '上海': '上海市',
        # ...
    }
    
    def normalize(self, province: str) -> str:
        """统一省份名称"""
        return self.PROVINCE_MAPPING.get(province, province)
```

### 4.4 高收益债券穿透

**问题**：需要识别可转债中的高收益品种（排除白名单）  
**解决方案**：

```python
# 1. 读取金融工具池（仅保留品种="可转债"）
df_tool = load_excel("金融工具池设置")
df_tool = df_tool[df_tool['品种'] == '可转债']

# 2. 通过ISIN码匹配穿透表
df_penetrate = load_excel("穿透高收益债券")
df = df.merge(df_penetrate[['ISIN', '类型']], on='ISIN', how='left')

# 3. 排除白名单（工具池中的可转债）
df_high_yield = df[~df['资产名称'].isin(df_tool['资产名称'])]
```

## 六、技术选型与优势

### 6.1 核心技术栈

| 层次       | 技术选型        | 理由                          |
|------------|-----------------|-------------------------------|
| 数据处理   | Pandas          | 强大的DataFrame操作，适合结构化数据 |
| 数据库访问 | pyodbc          | 支持Access数据库连接          |
| Web框架    | Streamlit       | 快速构建数据应用，无需前端开发 |
| 可视化     | Plotly          | 交互式图表，支持缩放/钻取      |
| 配置管理   | PyYAML          | 人类可读的配置格式            |
| 日志记录   | Loguru          | 简洁API，自动日志轮转         |

### 6.2 架构优势

1. **轻量化部署**：无需数据库服务器，仅依赖Python环境
2. **易于维护**：逻辑清晰分层，模块职责单一
3. **可扩展性**：新增限额维度仅需扩展Stage1/2
4. **数据可追溯**：按日归档，满足审计要求
5. **开发效率高**：Python生态丰富，代码简洁

### 6.3 性能优化

- **缓存机制**：Streamlit `@st.cache_data` 缓存数据加载
- **增量处理**：仅处理变更数据（可选）
- **并行计算**：Pandas矢量化操作，避免循环
- **内存优化**：大文件分块读取（`chunksize`）
