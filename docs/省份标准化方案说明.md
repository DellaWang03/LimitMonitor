# 省份名称标准化方案说明

## 📋 问题背景

### 发现的问题
在高风险省份集中度统计中，发现云南省和贵州省的总持仓数据与原始数据不一致：
- **云南省**：原始数据 64243.14，网页显示 62243.14（少了 2000）
- **贵州省**：原始数据 49500，网页显示 47500（少了 2000）

### 根本原因
数据处理流程中，债券持仓表与配置表通过省份字段进行left join关联：
- 债券持仓表中部分记录的省份字段为 `"云南"`、`"贵州"`
- 配置表中的省份名称为 `"云南省"`、`"贵州省"`
- 因为格式不匹配，导致这些记录的 `省份类别` 字段为空
- 在Stage2筛选高风险省份时（`df['省份类别'] == '高风险省份'`），这些记录被排除

## ✅ 解决方案

### 方案架构
创建统一的省份名称标准化工具，在数据关联前自动标准化省份名称。

### 核心组件

#### 1. 省份标准化工具类
**文件**: `src/common/province_normalizer.py`

**功能**:
- 维护全国34个省级行政区的标准名称映射表
- 支持多种省份名称变体的自动识别和转换
- 提供DataFrame列级标准化功能
- 提供数据质量验证和诊断功能

**映射规则**:
```python
{
    '云南': '云南省',
    '贵州': '贵州省',
    '北京': '北京市',
    '内蒙古': '内蒙古自治区',
    '内蒙': '内蒙古自治区',
    '广西': '广西壮族自治区',
    ...
}
```

**关键方法**:
- `normalize()`: 标准化单个或Series的省份名称
- `add_normalized_column()`: 在DataFrame中添加标准化列
- `validate_dataframe()`: 验证和诊断省份字段的标准化情况

#### 2. Stage1处理器修改
**文件**: `src/stage1/stage1_processor.py`

**修改位置**: 第777-797行（关联高风险省份表部分）

**修改内容**:
```python
# 原逻辑：直接使用原始省份字段merge
df.merge(
    df_high_risk_province[['日期', '省份名称', '省份类别']],
    left_on=['日期', '省份'],
    right_on=['日期', '省份名称'],
    how='left'
)

# 新逻辑：先标准化，再merge
# 1. 标准化债券持仓表的省份字段
df = ProvinceNormalizer.add_normalized_column(df, '省份', '省份_标准')

# 2. 标准化配置表的省份名称字段  
df_high_risk_province = ProvinceNormalizer.add_normalized_column(
    df_high_risk_province, '省份名称', '省份名称_标准'
)

# 3. 使用标准化字段进行merge
df.merge(
    df_high_risk_province[['日期', '省份名称_标准', '省份类别']],
    left_on=['日期', '省份_标准'],
    right_on=['日期', '省份名称_标准'],
    how='left'
)
```

**新增功能**:
- 自动计算并记录省份匹配率
- 当匹配率低于95%时，输出警告并列出未匹配的省份

#### 3. Stage2处理器修改
**文件**: `src/stage2/stage2_processor.py`

**修改位置**: 第258-275行（query_high_risk_province方法）

**修改内容**:
在读取配置表后，立即对省份名称字段应用标准化，确保后续所有使用该数据的地方都使用标准格式。

## 🔄 后续建议

### 1. 数据源规范化
建议在原始Excel文件中统一省份名称格式：
- 所有省份统一使用 "XX省" / "XX市" / "XX自治区" 格式
- 避免简称和全称混用

### 2. 数据质量监控
在每次运行后自动检查：
- 省份匹配率是否达标（>= 95%）
- 关键省份的持仓数据是否合理
- 是否有新的未识别省份名称

### 3. 定期审核
每季度审核一次：
- 映射表是否需要新增变体
- 数据质量报告
- 异常情况分析
