# 日期验证器修复说明

## 📅 修改日期
2026-01-26

## 🔧 修改内容

### 问题描述
原先的日期验证器在判断"前一个交易日（T-1）"时，直接从标准日期表中取小于今天的最大日期，未考虑"日期类别"字段。这导致在周一运行时，可能会错误地将周六识别为前一个交易日。

**错误示例**：
```
今天: 2026-01-26 (周一)
T-1日期: 2026-01-25 (周六)  ← ❌ 错误！
```

**正确结果**：
```
今天: 2026-01-26 (周一)
T-1日期: 2026-01-23 (周五)  ← ✅ 正确！
```

### 修改文件
`src/utils/date_validator.py`

### 修改细节

#### 1. `get_t_minus_1_date()` 方法（第51-100行）

**修改前逻辑**：
```python
# 找到<基准日期的最大交易日
valid_dates = df_dates[df_dates['日期'].dt.date < as_of_date]
t_minus_1 = valid_dates['日期'].max()
```

**修改后逻辑**：
```python
# 检查"日期类别"列是否存在
if '日期类别' not in df_dates.columns:
    raise ValueError("标准日期表缺少'日期类别'列")

# 先筛选出"工作日"类型的记录
working_days = df_dates[df_dates['日期类别'] == '工作日'].copy()

# 从工作日中找到<基准日期的最大日期
valid_dates = working_days[working_days['日期'].dt.date < as_of_date]
t_minus_1 = valid_dates['日期'].max()
```

**关键改进**：
- ✅ 添加"日期类别"列存在性检查
- ✅ 只从"工作日"记录中查找T-1
- ✅ 排除"节假日"类型的记录
- ✅ 更清晰的错误提示

#### 2. `get_business_date_info()` 方法（第183-216行）

**修改前逻辑**：
```python
# 判断今天是否是交易日
is_trading_day = today in df_dates['日期'].dt.date.values
```

**修改后逻辑**：
```python
# 判断今天是否是工作日（交易日）
if '日期类别' in df_dates.columns:
    # 筛选工作日
    working_days = df_dates[df_dates['日期类别'] == '工作日']
    is_trading_day = today in working_days['日期'].dt.date.values
else:
    # 兼容模式
    logger.warning("标准日期表缺少'日期类别'列，假设所有日期均为工作日")
    is_trading_day = today in df_dates['日期'].dt.date.values
```

**关键改进**：
- ✅ 只在"工作日"记录中判断今天是否为交易日
- ✅ 添加兼容模式处理缺少"日期类别"列的情况
- ✅ 周末/节假日将正确返回 `False`

#### 3. `get_standard_dates()` 方法（第24-49行）

**修改前日志**：
```python
logger.debug(f"加载标准日期表: {len(df)} 个交易日")
```

**修改后日志**：

if '日期类别' in df.columns:

    logger.debug(f"加载标准日期表: {len(df)} 条记录")

**关键改进**：
- ✅ 更准确的日志描述（"记录"vs"交易日"）
- ✅ 显示工作日统计信息

## 📋 标准日期表要求

修改后的代码要求标准日期表（`sample data/标准日期表.xlsx`）必须包含以下列：

| 列名 | 数据类型 | 说明 | 示例值 |
|-----|---------|------|--------|
| 日期 | Date | 日期 | 2026-01-26 |
| 日期类别 | String | 日期类型 | "工作日" 或 "节假日" |

### 示例数据

```
| 日期       | 日期类别 |
|-----------|---------|
| 2026-01-20 | 工作日   |
| 2026-01-21 | 工作日   |
| 2026-01-22 | 工作日   |
| 2026-01-23 | 工作日   |
| 2026-01-24 | 节假日   |
| 2026-01-25 | 节假日   |
| 2026-01-26 | 节假日   |  ← 春节假期
| 2026-01-27 | 节假日   |
| 2026-01-28 | 节假日   |
| 2026-01-29 | 节假日   |
| 2026-01-30 | 工作日   |
```

**重要**：
- ✅ "工作日" = 交易日（正常工作的工作日）
- ✅ "节假日" = 非交易日（包括周末、法定节假日、调休日等）

## 🔄 向后兼容性

- ✅ 如果标准日期表**有**"日期类别"列：使用新逻辑（只选工作日）
- ⚠️ 如果标准日期表**缺少**"日期类别"列：
  - `get_t_minus_1_date()` 会抛出错误，提示添加该列
  - `get_business_date_info()` 会发出警告，但继续使用旧逻辑

## 📌 注意事项

1. **标准日期表必须及时更新**
   - 建议至少包含未来3-6个月的日期数据
   - 包含所有法定节假日和调休安排

2. **日期类别值必须准确**
   - 严格使用"工作日"和"节假日"两个值
   - 不要使用其他变体（如"交易日"、"周末"等）

3. **春节、国庆等长假期要特别标注**
   - 确保假期中的所有日期都标记为"节假日"
   - 确保调休的工作日标记为"工作日"

## 📝 总结

- **问题根因**：未使用"日期类别"字段区分工作日和节假日
- **修复方式**：在筛选 T-1 时只选择"日期类别"为"工作日"的记录
- **兼容性**：对缺少"日期类别"列的情况提供明确错误提示
- **验证**：运行测试脚本或完整流程，检查 T-1 日期是否正确
