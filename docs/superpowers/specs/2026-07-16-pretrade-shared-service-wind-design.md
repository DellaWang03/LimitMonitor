# 交易前共同内核服务与 WindPy 主数据设计

状态：已获业务确认，待评审本文件后编制实施计划  
日期：2026-07-16  
权威依据：[交易前试算共同内核权威规格](../../PRETRADE_SHARED_CORE_SPEC.md)

## 1. 目标与边界

本设计只实现以下两个新增交易前功能的后端共同服务：

1. 指定债券和拟买入账户，返回交易前 PR 可购剩余额度；
2. 指定一揽子债券、拟买 PR 金额和拟买入账户，返回交易后是否超限。

每日 Stage0、Stage1、Stage2 的业务口径保持不变。新增服务不能复制或改写任何限额公式、路由、覆盖关系、分组或边界判断；它只能构造交易增量、调用 `ProductionRiskKernel`，并从该次内核输出提取结果。

本阶段不修改既有展示页面、既有展示快照、日常 Stage0 的主体代码解析流程或数据库表结构。Wind 的实时结果不落库、不缓存、不写本地业务文件。

## 2. 数据来源与账户分类

服务只读取 `PretradeContextStore` 的唯一 current 指针所指向的 27 项共同内核输入。没有可用 current、输入完整性校验失败或 current 与既有展示归档的数据日期不一致时，服务返回“数据同步中”，不混用批次。

持仓识别只使用快照中的完整持仓事实输入。持仓债的主数据只来自该快照；若持仓事实存在但主数据不完整，返回 `MISSING_SNAPSHOT`，不得向 Wind 补齐。只有完整持仓事实确认没有持仓时，才调用 WindPy。

账户分类严格复用冻结上线提交 `579af695...` 的 Excel M 逻辑：

- 账户名严格等于 `做市交易部做市业务` 时，业务分类为 `做市业务`；
- 所有其他账户名均为 `自营业务`。

交易前服务不新增账户白名单或拒绝规则，避免比上线逻辑更严。

## 3. WindPy 适配器

新增一个独立的、请求期存在的 `WindPyBondMasterProvider`。它不能复用或重新启用既有 `wind_code_resolver`：后者继续服务于日常 Stage0 的 Excel `To_WindCode()` 静态主体代码解析，且继续禁用 Python Wind 查询。

新适配器通过 Wind Python API 获取非持仓债的最小必要主数据，规范化成共同内核输入行。字段契约包括：

- 债券标识与归并：输入代码、主证券代码、ISIN、债券名称；
- 集中度：债券余额；
- 主体关系：发行人名称、发行人 Wind 代码、实控人、担保人、担保人 Wind 代码；
- 分类事实：债券分类、债券类型、发行人类型、是否城投、债券类别、Wind 行业、省份。

具体 Wind 字段代码只封装在该适配器中，并以固定 Wind 响应夹具验证。它不从 Wind 取得或推断债券池、主体池、担保准入、内部实控人调整、发行人类型调整、高风险类别、限额配置、持仓、分母或高收益规则；这些始终来自交易前 current 快照并由共同内核处理。

每次调用返回规范记录、`wind_fetched_at`、Wind 可用数据日期（若响应提供）及字段级完整性。任何必需字段为空、Wind 未安装或未启动、调用失败、代码多义或响应异常，均返回 `MISSING_MASTER` 与具体原因；不得补零、默认分类、推断为不适用或降级读取其他来源。页面只展示本次获取时间与数据日期，不保存原始响应或规范结果。

## 4. 交易覆盖与共同内核调用

`TradeOverlayBuilder` 在内存中复制 current 快照输入，将每笔规范交易行追加到下列三张生产输入：

- `债券持仓明细表`；
- `债券持仓明细表_信用债`；
- `债券持仓明细表_全量债券监管集中度`。

交易行的日期固定为快照业务日期。篮子行的 `库存数量(万)_PR` 为用户给出的有限正数。非业务字段保持空值，不伪造默认业务事实。

高收益年度预计结算全价成本有一条额外、但仍属于共同内核的生产路径。现有 Stage2 将成本输入分为 `债券持仓表_核算系统` 与 `穿透高收益_投资本金规模` 后再合并。为与上线口径一致，实现会先从当前生产代码抽离同一高收益路由函数：

- 若该函数把交易行路由到核算系统分支，则将用户的预计结算全价成本（万元）换算为 `全价成本(元)`，只追加到 `债券持仓表_核算系统`；
- 若路由到穿透高收益分支，则只追加到 `穿透高收益_投资本金规模`；
- 同一交易行绝不同时追加到两个成本输入；不属于高收益的行不追加年度成本输入；
- 已识别为高收益但未提供大于零的全价成本时，PR 维度仍照常重算，年度成本维度标记为不可计算。

这个路由函数只能从现有生产 Stage2 提取并以金样证明零差异，不能在交易前适配器重新实现高收益判定。

单券可购额度查询不接受用户零金额输入。为识别非持仓债在当前快照下的适用限额维度，服务在内存中构造一条只读零金额探针行并执行相同完整重算；该探针不代表交易、不落库、不缓存，也不对外暴露为零金额交易。

追加完成后，服务调用 `ProductionRiskKernel` 的 Stage1、Stage2。高收益识别与成本路由仍复用生产内核的穿透高收益债券表、金融工具池和账户规则，不能把 Wind 的标签作为额外规则。

## 5. 结果模型与状态

`PretradeResultAdapter` 只读取本次共同内核输出，不重新计算限额公式。结果同时保留生产业务结果和下列独立状态：

- `applicability_status`：`APPLICABLE`、`NOT_APPLICABLE`、`UNDETERMINED`；
- `data_quality_status`：`COMPLETE`、`MISSING_MASTER`、`MISSING_LIMIT`、`MISSING_SNAPSHOT`、`MISSING_INPUT`、`INVALID_INPUT`；
- `calculation_status`：`CALCULATED`、`UNCOMPUTABLE`。

单券结果对全部必需 `PR_WAN` 维度读取交易前剩余，给出最紧原始剩余 `raw_pr_remaining_wan`；只有全部必需维度可计算时，给出 `purchasable_pr_cap_wan = max(0, raw_pr_remaining_wan)`。高收益年度预计结算全价成本剩余独立输出，不与 PR 额度求最小值。

篮子结果读取交易后完整重算的生产结果。债券、主体、实控人、担保人、地域、行业和高收益年度范围由内核按既有逻辑自然合并；适配器不得按页面输入自行相加或扣减。总体状态优先级固定为：

1. 任一已确认维度交易后剩余小于零：`已超限`；
2. 没有确认超限，但存在必需不可计算维度：`不可计算`；
3. 其余：`未超限`。

剩余额度等于零不超限，业务判断不得引入数值容差。

## 6. 验收

实现前后必须维持生产 Stage0/1/2 冻结金样零差异。新增服务至少覆盖：

1. 持仓债通过 current 快照进入共同内核；
2. 非持仓债通过固定 WindPy 响应夹具进入同一内核；
3. 持仓主数据不完整时不得调用 Wind；
4. Wind 必需字段缺失、调用失败及多义响应均不可计算；
5. 单券零金额探针与单行篮子在对应维度上的一致性；
6. 篮子拆单、合单和行顺序不影响结果；
7. 共享主体、实控人、担保人、地域、行业和高收益年度范围的合并；
8. 高收益全价成本与 PR 金额严格隔离，且成本交易行只进入一条既有生产输入路径；
9. 不读取 Excel、ACCDB、`data/current`、展示快照或本地业务配置；
10. 真实 Wind 环境仅验证 `WindPy` 连通性和字段完整性，不以实时结果作为回归预期。

本机当前 Python 环境未安装 `WindPy`，因此自动化测试必须使用内存响应夹具；真实连通性验收在安装 Wind 终端授权与 `WindPy` 的运行环境执行。

- 不创建 Wind 主数据表、缓存、审计运行表、额外数据库账号或 TEST 环境；
- 不修改既有展示快照或其余页面；
- 不通过读取旧展示结果、旧单券页面代码或结果表反推业务规则；
- 不在本阶段完成前端视觉优化。
